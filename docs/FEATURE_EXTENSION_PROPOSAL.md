# Votle 기능 추가 요구사항 명세서

## 1. 문서 목적

기존 게시글 중심 커뮤니티를 **투표 중심 커뮤니티 Votle**로 확장하기 위해 추가할 기능과 개발 범위를 정의한다.

개발 기간은 4주이며, 투표 기능과 실시간 인기글을 필수 범위로 한다. 검색과 마이페이지는 필수 기능을 완료하고 일정이 남을 경우 진행하는 선택 범위로 둔다.

## 2. 서비스 개요

Votle은 사용자가 일상적인 고민이나 의견을 게시글과 투표로 공유하고, 다른 사용자들의 선택과 반응을 확인할 수 있는 커뮤니티 서비스다.

기존 게시글, 댓글, 좋아요 기능을 유지하면서 투표 참여와 인기 투표 탐색을 서비스의 주요 사용 흐름으로 추가한다.

## 3. 기능 우선순위

| 우선순위 | 기능 | 개발 여부 |
|---|---|---|
| 1 | 투표 기능 | 필수 |
| 2 | 실시간 인기글 | 필수 |
| 3 | 검색 | 일정 여유 시 진행 |
| 4 | 마이페이지 | 일정 여유 시 진행 |

검색과 마이페이지는 4주 내 구현을 보장하는 기능이 아니다. 투표와 실시간 인기글의 구현 및 안정화가 완료된 이후에만 착수한다.

## 4. 투표 기능 요구사항

### 4.1 투표 생성

- 로그인 사용자는 게시글 작성 시 투표를 추가할 수 있어야 한다.
- 게시글은 투표 없이도 작성할 수 있어야 한다.
- 하나의 게시글에는 하나의 투표만 등록할 수 있어야 한다.
- 투표에는 제목과 2개 이상 5개 이하의 선택지를 입력할 수 있어야 한다.
- 투표 종료 시각을 설정할 수 있어야 한다.
- 조건을 충족하지 않은 투표는 등록할 수 없어야 한다.

### 4.2 투표 참여

- 로그인 사용자는 진행 중인 투표에 참여할 수 있어야 한다.
- 사용자는 하나의 선택지만 선택할 수 있어야 한다.
- 동일한 사용자는 같은 투표에 중복으로 참여할 수 없어야 한다.
- 비로그인 사용자가 투표를 시도하면 로그인이 필요하다는 안내를 제공해야 한다.
- 종료된 투표에는 참여할 수 없어야 한다.

### 4.3 투표 결과

- 투표 참여 후 전체 참여 인원과 선택지별 결과를 확인할 수 있어야 한다.
- 각 선택지의 득표수와 득표율을 표시해야 한다.
- 사용자가 선택한 항목을 구분해서 표시해야 한다.
- 종료된 투표는 최종 결과와 종료 상태를 표시해야 한다.
- 득표수와 득표율은 실제 참여 결과와 일치해야 한다.

### 4.4 투표 수정 및 종료

- 투표 참여자가 없을 때는 작성자가 투표 내용을 수정할 수 있어야 한다.
- 한 명 이상 참여한 이후에는 선택지 변경을 제한해야 한다.
- 작성자는 진행 중인 투표를 조기 종료할 수 있어야 한다.
- 종료된 투표는 다시 진행 상태로 변경할 수 없어야 한다.

## 5. 실시간 인기글 요구사항

### 5.1 인기글 선정

- 최근 사용자 반응이 활발한 게시글을 인기글로 선정해야 한다.
- 투표 참여, 댓글, 좋아요, 조회 등의 반응을 종합적으로 반영해야 한다.
- 오래된 누적 반응만으로 인기글이 계속 유지되지 않도록 최근 반응을 중요하게 반영해야 한다.
- 삭제되거나 운영상 제한된 게시글은 인기글에서 제외해야 한다.

### 5.2 인기글 표시

- 게시글 목록에서 현재 인기글을 별도 영역으로 확인할 수 있어야 한다.
- 인기글은 순위와 함께 표시해야 한다.
- 인기글 목록에는 제목, 작성자, 현재 투표 상태, 참여 인원 등 핵심 정보를 표시해야 한다.
- 인기 순위가 변경되면 사용자가 새로고침하지 않아도 일정 시간 내 화면에 반영되어야 한다.
- 인기글 갱신 기능에 문제가 생겨도 일반 게시글 목록은 정상적으로 이용할 수 있어야 한다.

## 6. 선택 기능 요구사항

### 6.1 검색

투표와 실시간 인기글을 완료한 후 일정이 남을 경우 구현한다.

- 게시글 제목과 본문을 키워드로 검색할 수 있어야 한다.
- 검색 결과에서 검색어와 일치하는 내용을 강조해야 한다.
- 검색 결과가 없을 경우 빈 상태 안내를 제공해야 한다.
- 삭제되거나 운영상 제한된 게시글은 검색 결과에서 제외해야 한다.

### 6.2 마이페이지

검색 기능까지 완료한 후 추가 일정이 남을 경우 구현한다.

- 사용자는 자신이 작성한 게시글을 확인할 수 있어야 한다.
- 사용자는 좋아요한 게시글을 확인할 수 있어야 한다.
- 사용자는 자신이 참여한 투표를 확인할 수 있어야 한다.
- 작성글, 받은 좋아요, 댓글 등 활동 요약을 확인할 수 있어야 한다.

## 7. 비기능 요구사항

- 중복 투표나 종료 후 투표 등 잘못된 참여가 서버에서도 차단되어야 한다.
- 여러 사용자가 동시에 투표해도 결과 집계가 정확해야 한다.
- 인증이 필요한 기능은 비로그인 상태에서 사용할 수 없어야 한다.
- 주요 기능은 데스크톱과 모바일 환경에서 모두 사용할 수 있어야 한다.
- 기능별 정상 상황과 예외 상황에 대한 테스트가 작성되어야 한다.
- 오류가 발생하면 사용자가 이해할 수 있는 안내를 제공해야 한다.

## 8. 개발 일정

| 주차 | 목표 |
|---|---|
| 1주 차 | 투표 생성 및 조회 기능 구현 |
| 2주 차 | 투표 참여, 결과, 수정 및 종료 기능 구현 |
| 3주 차 | 실시간 인기글 선정 및 화면 반영 기능 구현 |
| 4주 차 | 테스트, 오류 처리, 안정화 및 발표 준비 |

검색과 마이페이지는 위 일정이 계획보다 빠르게 완료된 경우에만 4주 차 안정화 작업을 방해하지 않는 범위에서 진행한다.

## 9. 완료 기준

다음 조건을 모두 만족하면 필수 기능 구현이 완료된 것으로 본다.

- 게시글 작성 시 투표를 생성할 수 있다.
- 로그인 사용자가 투표에 한 번만 참여할 수 있다.
- 참여 결과와 최종 결과를 정확하게 확인할 수 있다.
- 투표 수정 및 종료 규칙이 정상적으로 적용된다.
- 최근 반응을 기준으로 인기글이 선정된다.
- 인기 순위 변경이 일정 시간 내 사용자 화면에 반영된다.
- 비로그인, 중복 참여, 종료된 투표 등 예외 상황이 처리된다.
- 주요 기능을 시연하고 기능별 동작과 예외 상황을 설명할 수 있다.

## 10. 승인 요청 사항

강사님께 다음 범위가 4주 프로젝트에 적절한지 확인을 요청드린다.

1. 투표 기능과 실시간 인기글을 필수 구현 범위로 설정한다.
2. 투표는 단일 선택 방식이며 사용자당 한 번만 참여할 수 있도록 제한한다.
3. 투표 생성, 참여, 결과, 수정 제한, 종료까지를 하나의 완성된 기능 범위로 본다.
4. 검색과 마이페이지는 일정이 남을 경우에만 진행하는 선택 기능으로 둔다.
5. 4주 차에는 새로운 기능 추가보다 테스트, 안정화, 기능 설명 준비를 우선한다.
